  - Covered keys: `catalog.<b>`, `tabs.<u>`, `customers`, `queue`, `lookups`, `settings`.
  - If only the old key exists, its value is copied to the new key. If both exist, the new value wins, except `queue`, which is merged by id so no unsynced invoice is lost.
  - The old key is removed only after the write succeeds. A corrupt queue or a quota error keeps the old key so the next load retries. Everything is wrapped in try/catch.
  - The app has no IndexedDB.
  - SW cache `vx-pos-v1` → `vx-sale-v2`; the existing activate handler deletes caches with other names.
